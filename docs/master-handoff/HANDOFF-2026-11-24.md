## What we are doing

Heart of Columbus is a directory of independent Columbus, Indiana businesses that
is becoming a positive, grassroots local news outlet. As of today the site is
launched (indexed, nothing marked preview), and the job is making it read like a

### The rules for history writing (not negotiable)

- Every new fact comes from a source **listed with that article** and **read in
  your session**. Never from memory. If you add a source, add it to `sources`.
- No invented quotes, people or numbers. Quote only what a source prints, exactly.
- Where sources disagree, say so in the text ("the paper's 2022 history says
  five generations; its 2015 sale story said six").
- Attribute claims that only one source makes ("The Republic reports...").
- No dashes anywhere a reader sees (no em dash, no en dash, no spaced hyphen);
  the build and tests fail on them. Use curly apostrophes (’) like the rest of the file.
- When you re-read an article's sources, set `checked: '2026-11-24'` (today's
  date) on it: `x({ checked: 'YYYY-MM-DD', slug: ... })`.
- Every history article needs at least two sources (a test enforces it).
- Every expanded piece is a change to approved text. Tell Jake which ones changed
  so he can reread them; `src/data/history/signoff.mjs` holds the approvals. He
  reread and approved everything expanded through 2026-11-24; anything you
  change after that needs his reread again.
- Don't expand the `/history/blair/` pieces. They summarize Brian Blair's
  Republic reporting and are short on purpose. Fix errors only.
- Skip pieces whose new material is national politics rather than local history
  (we left the Pence piece alone for that reason).

### How the work is done

1. Pick short articles: `words(a)` in `src/data/history/index.mjs`, sorted, from
   `ARTICLES`. Note each article's `sources` hosts.
2. Fetch the sources with `curl` (a desktop browser user agent helps), strip the
   HTML to text, and read only what's relevant.
3. Rewrite the article's `body` array. A small Python helper that finds
   `slug: '<slug>'`, then replaces everything from `body: [` up to
   `],\n    sources:`, is the safest way. For small fixes, do exact string
   replacements and assert each one matches exactly once.
4. `npm run build && npm test` (292 tests at last count), then commit, PR, merge.

## Traps we hit today

- **Parallel sessions.** Another session expanded four of the same articles
  while this one did; the merge conflicted. Keep `main`'s live version when two
  sessions wrote the same piece, and check `git log HEAD..origin/main` first.
- **Don't `git stash` in the middle of a merge.** It drops `MERGE_HEAD`; redo the
  merge instead.
- **Tests needing packages.** `npm install` after pulling if a test fails with
  `ERR_MODULE_NOT_FOUND` (main added `@netlify/blobs`). Don't commit the
  `package-lock.json` churn that `npm install` leaves behind unless it's intended.
- **A source cited for one sentence isn't wrong** because it says nothing about
  the rest of the article (Chrome flagged the Ethnic Expo citation on
  2020s/columbus-passes-fifty-thousand; it supports the Expo sentence, and the
  census numbers come from Wikipedia).
