# Heart of Columbus SEO audit

Audited October 26, 2026. Target: https://heartofcolumbus.netlify.app/.

## Executive finding

Organic search is intentionally disabled. The live homepage returns HTTP 200
with `X-Robots-Tag: noindex, nofollow`, and its HTML repeats the same directive.
Netlify applies the header sitewide. README.md and CLAUDE.md explicitly require
preview indexing protection until businesses sign on. This change preserves
that policy. Metadata improvements alone cannot make these pages indexable.

## Evidence and priorities

| Priority | Finding | Evidence | Resolution |
| --- | --- | --- | --- |
| Launch blocker | Search indexing disabled | Live response header, live meta tag, netlify.toml | Retained per project policy; launch steps below |
| High | No canonical URLs | Live homepage has zero canonical tags; shared shell has none | Added one absolute self canonical per generated content URL, excluding 404 |
| Medium | Incomplete social metadata | Live og:image is relative `/og.png`; no og:url or Twitter cards | Absolute image and page URLs, image dimensions and alt, site name, language locale, Twitter large image cards |
| Medium | No explicit crawler discovery file | No robots.txt in public/ or generated by original build | Build now writes robots.txt, permits crawling so noindex can be read, advertises sitemap only when one exists |
| Medium | Sitemap launch behavior fragile | Optional original sitemap could be empty; URL generation duplicated | Centralized output URL generation, XML escaping, excludes noindex and non-content files, suppresses empty sitemap |
| Medium | Configurable origin can produce inconsistent URLs | Original HOC_ORIGIN concatenated strings without normalization | Normalize trailing slash; reject path, query, fragment, credentials and non-HTTP origins |
| Medium | Heavy homepage | Downloaded HTML is 440,533 bytes; 360 img elements | Further performance work recommended; not a measured Core Web Vitals failure |
| Medium | Missing intrinsic image dimensions | All 360 live homepage img elements lack width/height attributes | Added measured dimensions to shared category icons (512 x 512) and cover artwork (1600 x 700); other image templates remain follow-up work |

## Existing strengths

The live homepage has one H1 and a location-specific title and description.
Every homepage image has an alt attribute; decorative images can appropriately
use an empty one. The build emits static HTML instead of requiring JavaScript
to discover business content. Category, neighborhood and business pages exist
as individual URLs. Existing structured data covers businesses, landmarks,
trips and breadcrumbs, with tests comparing facts to page content. English and
Spanish guide templates already emit language alternates. No business facts,
reviews or ratings were invented in this SEO work.

## Changes implemented

`src/seo.mjs` finalizes metadata from each output path. This avoids accidentally
canonicalizing all pages to the shell's default `/` path. Query parameters and
fragments are not included in these content canonicals. Existing Spanish
alternates are preserved. The 404 remains noindex and gets no canonical.

The build retains the existing `HOC_SITEMAP=1` switch. It writes no sitemap
when all pages are noindex, and writes a robots sitemap reference only when
there are eligible URLs. This switch does not launch the site, change page
indexability or override Netlify headers.

Shared cover and category images now include measured intrinsic sizes and
asynchronous decoding. Existing CSS still controls rendered dimensions.
The 1200 x 630 social image dimensions were verified against public/og.png.

## Launch sequence after the preview policy is retired

1. Decide which directory and guide pages are ready for public search. Keep
   unapproved storefront demos, saved lists, pickup tickets, private boards,
   inboxes, review pages and errors noindex. Spanish pages say translation is
   under review; get that review before including them in an indexable launch.
2. Set HOC_ORIGIN to the chosen canonical HTTPS origin. If moving to a custom
   domain, configure permanent host redirects at Netlify and verify them.
3. Replace the blanket Netlify `X-Robots-Tag` with appropriate scoped preview
   and utility protections. Configure deploy previews separately. Changing
   only HTML robots tags will not overcome the current response header.
4. Set preview:false only on approved page templates. Do not flip the shared
   default globally because that can expose utility and demo pages to search.
5. Enable HOC_SITEMAP=1. Inspect sitemap URLs and confirm every included URL
   returns HTTP 200 and has no noindex in either HTTP headers or HTML.
6. Verify ownership in Google Search Console, submit the sitemap, and inspect
   the homepage plus representative category, business and guide URLs.
7. Recheck status codes on missing URLs and verify redirects, canonicals,
   robots.txt, hreflang reciprocity and structured data on the deployed host.

## Next improvements

* Run mobile Lighthouse and collect field Core Web Vitals. Investigate LCP,
  INP and CLS before claiming a performance score or ranking impact.
* Reduce homepage card volume while keeping crawlable links to category and
  neighborhood archives. Measure the HTML and image request reduction.
* Generate appropriately sized WebP or AVIF card variants and responsive
  srcset values. Preserve full resolution art where it is actually displayed.
* Finish image width/height coverage; do not guess photo aspect ratios. Keep
  the above-the-fold LCP image eager and prioritize it only after measuring.
* Review category and neighborhood descriptions for useful, sourced local
  context. Avoid mass generating repetitive keyword paragraphs.
* Review business listing freshness and distinctiveness before indexing all
  listings. Display sourced, checked details and functional first-party links.
* Validate eligible structured data with Google's Rich Results Test. Existing
  JSON parsing tests do not prove rich-result eligibility or guarantee display.

## Validation and limits

`npm test`: 102 passed, zero failed. Build generated 1,208 pages. New tests
check canonical URLs and absolute social images on every generated HTML page,
preserve preview robots directives, exclude noindex pages from sitemap data,
and check metadata entity handling and Spanish social locale.

The audit combines a direct HTTP fetch of the live homepage with repository
and complete generated-page checks. It is not a full live network crawl of
1,208 deployed URLs. No Search Console, traffic, rankings, backlinks, field
performance or mobile screenshot results were available. No Lighthouse score
is claimed. These changes need deployment before they affect live responses.

### Measured changes

Compared with the original downloaded homepage, generated homepage HTML went
from 440,533 to 371,437 bytes (15.7% smaller). Image elements fell from 360 to
258 (28.3% fewer). The originals for all 51 category cover images total
2,364,650 bytes; corresponding 640-pixel WebP assets total 301,458 bytes
(87.3% smaller). The latter is a comparison of the entire cover library, not
a claim about actual transferred homepage bytes or measured browser speed.
Responsive markup adds some HTML overhead; the total HTML reduction above
already includes that overhead.

Validation after the second pass: `npm test` passed all 106 tests. This
includes checking local image sizes and all responsive candidate files across
the 1,208 generated pages, checking reciprocal alternates, and enforcing a
homepage HTML/image-count budget. The full internal link and JSON-LD tests
also pass. These checks do not replace mobile visual validation.

### Build details

`npm ci` installs the pinned Sharp dependency. `npm run build` generates
responsive variants into dist/assets/images/ and writes a manifest there.
Encoders run four images at a time to limit memory usage. This adds build
work but requires no image processing at request time. Dynamic cards created
by browser scripts retain their existing artwork behavior; this pass optimizes
the generated static HTML. The preview server now serves WebP and JSON with
their correct content types.
